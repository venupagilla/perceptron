01 · Getting Started with Java

Getting started with Java

The language, its editions, tooling, and your first program.

1What is Java?

  • Java is a high-level, object-oriented, platform-independent programming language.
  • Developed by Sun Microsystems (now owned by Oracle) in 1995.
  • Widely used for web applications, Android apps, enterprise software, games, and more.

2Key features of Java

  • Platform Independent — Java code is compiled into bytecode (.class) that runs on any OS with the Java Virtual Machine (JVM).
  • Simple and Secure — easy syntax (similar to C++), automatic memory management, no pointers.
  • Object-Oriented — supports encapsulation, inheritance, polymorphism, abstraction.
  • Robust — strong type checking, exception handling, garbage collection.
  • Multithreaded — built-in support for concurrent execution.

3Java editions

EditionDescription
Java SE (Standard Edition)Core Java for desktop applications.
Java EE / ME (Enterprise / Micro Edition)For web and mobile/embedded systems.
Jakarta EESuccessor to Java EE (community-driven).

4Java Development Kit (JDK)

  • Required tools: javac (compiler), java (runner), javadoc, etc.
  • Download from: Oracle JDK or OpenJDK (free and open-source).
  • Latest versions (as of 2025): Java 21+ (LTS), Java 23/24/25 (non-LTS).

5Setting up the Java environment

  1. Download and install the JDK from oracle.com or openjdk.java.net.
  2. Set environment variables:
    • JAVA_HOME → path to the JDK folder.
    • Add %JAVA_HOME%\bin to PATH.
  3. Verify installation:
bash 
java -version
javac -version

6First Java program (Hello World)

java 
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
  • public class HelloWorld — class name must match the filename (HelloWorld.java).
  • public static void main(String[] args) — entry point of the program.
  • System.out.println() — prints output to the console.

7Compilation and execution

  1. Save the file as HelloWorld.java.
  2. Compile → generates HelloWorld.class (bytecode):
bash 
javac HelloWorld.java
  1. Run:
bash 
java HelloWorld

8Popular IDEs for Java

  • IntelliJ IDEA (most popular)
  • Eclipse
  • NetBeans
  • Visual Studio Code (with Java extensions)

01 · Language Basics

Keywords, variables, identifiers, and data types

The building blocks of every Java program.

1Keywords

  • Keywords (also called reserved words) are predefined words with special meaning in Java.
  • They cannot be used as identifiers (variable names, class names, etc.).
  • All keywords are in lowercase.
  • Total: 50 keywords (as of Java 23+; 2 unused: const, goto).

Common keywords:

CategoryExamples
Access Modifierspublic, private, protected
Class/Interfaceclass, interface, enum, record
Control Flowif, else, switch, case, default, for, while, do, break, continue, return
Exception Handlingtry, catch, finally, throw, throws
Data Typesint, float, double, boolean, char
Modifiersstatic, final, abstract, synchronized, volatile
Othersnew, this, super, instanceof, void, native, strictfp
Note: true, false, null are literals, not keywords.

2Identifiers

  • Identifiers are names given to variables, methods, classes, interfaces, etc.

Rules for naming identifiers:

  1. Can consist of letters (a–z, A–Z), digits (0–9), underscore _, and dollar sign $.
  2. Cannot start with a digit.
  3. Cannot be a keyword or reserved word.
  4. Case-sensitive (e.g., age and Age are different).
  5. No length limit (but practically reasonable).

Naming conventions (best practices):

  • Variables/Methods: camelCase → myVariable, calculateTotal()
  • Classes/Interfaces: PascalCase → MyClass, Runnable
  • Constants: UPPER_SNAKE_CASE → MAX_VALUE, PI
  • Packages: all lowercase → com.example.myapp

Valid examples:

java 
int age;
double _salary;
String $userName;
int student2;

Invalid examples:

java 
int 2age;        // starts with digit
int class;       // keyword
int my-var;      // hyphen not allowed

3Variables

  • A variable is a named storage location in memory that holds a value.
  • Must be declared before use.

Syntax:

java 
dataType variableName;               // Declaration
dataType variableName = value;       // Declaration + Initialization

Types of variables:

  1. Local Variables — declared inside methods/blocks; must be initialized before use; no default value.
  2. Instance Variables — declared inside the class but outside methods; stored in the object; default values provided.
  3. Static (Class) Variables — declared with the static keyword; one copy per class.
java — example 
public class Example {
    int instanceVar;              // Instance variable (default: 0)
    static int staticVar = 100;   // Static variable

    void method() {
        int localVar = 50;         // Local variable (must initialize)
    }
}

Java is statically typed → the variable type must be declared.

  • Classes, interfaces, arrays, String, etc.
  • Default value: null

  • Integer: 100, 0xFF (hex), 077 (octal), 100L (long)
  • Floating: 3.14, 2.5f (float)
  • Character: 'A', '\n', '\u0041'
  • String: "Hello World"
01 · Language Basics

Type conversion in Java

Widening, narrowing, wrappers, and the classic interview traps.

1Types of type conversion

Implicit conversion (widening / automatic)

  • Done automatically by the JVM.
  • No data loss (smaller → larger type).
  • Order (widening hierarchy): byte → short → int → long → float → double and char → int → long → float → double.
java — example 
int i = 100;
long l = i;      // Automatic
float f = l;     // Automatic
Interview tip: safe, no precision loss — except when int → float or long → float/double (possible minor precision loss for very large values).

Explicit conversion (narrowing / casting)

  • Done manually by the programmer.
  • Potential data loss or truncation.
  • Syntax: (targetType) value
java — example 
double d = 100.04;
long l = (long) d;    // 100 (fractional part lost)
int i = (int) l;      // 100

Common pitfall:

java 
int i = 128;
byte b = (byte) i;    // b = -128 (overflow/truncation)

2Key interview questions & points

Q: Can you convert between boolean and other types?

No. Boolean cannot be converted to/from any other primitive type (neither implicit nor explicit).

Q: Difference between widening and narrowing?

Widening: automatic, safe, no cast needed. Narrowing: manual cast required, risk of data loss.

Q: What happens when converting float/double to int?

The fractional part is truncated (not rounded).

int x = (int) 10.9;   // x = 10
int y = (int) -10.9;  // y = -10

Q: char to int conversion?

char is unsigned 2-byte (0–65535). Converts to its Unicode value.

char c = 'A';
int i = c;            // i = 65
char c2 = (char) 97;  // c2 = 'a'

Q: Is casting allowed between unrelated types?

No. Compile-time error unless using an explicit cast (and the types are compatible in some way). Example: int to String → not allowed directly (need String.valueOf() or Integer.toString()).

3Type conversion with wrapper classes (common in interviews)

Parsing strings to primitives

java 
int i = Integer.parseInt("123");        // String → int
double d = Double.parseDouble("12.34"); // String → double
boolean b = Boolean.parseBoolean("true");

Risk: throws NumberFormatException if the string is invalid.

Converting primitives to String

java 
String s1 = String.valueOf(123);           // int → String
String s2 = Integer.toString(123);
String s3 = 123 + "";                      // Common trick

Autoboxing & unboxing (Java 5+)

Primitive ↔ Wrapper automatic conversion.

java 
Integer obj = 10;        // Autoboxing (int → Integer)
int prim = obj;          // Unboxing (Integer → int)
Interview gotcha: unboxing null → NullPointerException.
java 
Integer obj = null;
int i = obj;             // NPE

4Common interview code traps

java 
byte b1 = 10;
byte b2 = 20;
byte b3 = (byte)(b1 + b2);  // Why cast needed?
// b1 + b2 → int (binary numeric promotion), so explicit cast required

01 · Language Basics

Control structures in Java

Decision-making, looping, and branching statements.

1Types of control structures

  • Decision-Making (Conditional): if, if-else, if-else-if ladder, switch, ternary operator.
  • Looping (Iteration): for, enhanced for (for-each), while, do-while.
  • Branching (Transfer): break, continue, return.

2Decision-making statements

A. if, if-else, if-else-if

java 
if (condition) {
    // execute if true
} else if (anotherCondition) {
    // execute if above false and this true
} else {
    // execute if all false
}
Interview tip: conditions must be boolean. No non-zero = true like C/C++.

B. Switch statement (traditional & enhanced)

  • Traditional Switch (pre-Java 14): supports int, byte, short, char, String, enum, wrapper classes; requires break to avoid fall-through.
java — traditional 
switch (value) {
    case 1: System.out.println("One"); break;
    case 2: System.out.println("Two"); break;
    default: System.out.println("Other");
}
  • Enhanced Switch (Java 14+) — more concise:
java — enhanced 
switch (value) {
    case 1 -> System.out.println("One");
    case 2 -> System.out.println("Two");
    default -> System.out.println("Other");
}
  • Switch Expression (Java 14+) — returns a value:
java — expression 
String result = switch (day) {
    case "MON", "TUE" -> "Weekday";
    case "SAT", "SUN" -> "Weekend";
    default -> "Invalid";
};
  • Uses -> (no fall-through) or yield in block form.

Interview questions:

Q: Can switch accept long or float?

No (compile error).

Q: Can case labels be duplicate?

No.

Q: What happens without break?

Fall-through (executes the next cases).

C. Ternary operator

java 
result = (condition) ? valueIfTrue : valueIfFalse;
  • Shorthand for simple if-else.
  • Pitfall: both expressions must return a compatible type.

3Looping statements

A. for loop

java 
for (initialization; condition; update) {
    // body
}

All three parts are optional.

java — infinite 
for(;;) { }  // Infinite loop

B. Enhanced for loop (for-each) — Java 5+

java 
for (Type var : collection/array) {
    // body
}
  • Read-only access. Cannot modify array/collection elements directly.
  • Interview gotcha: cannot easily iterate with an index (use a traditional for).

C. while loop

java 
while (condition) {
    // body
}

Checks the condition before execution.

D. do-while loop

java 
do {
    // body
} while (condition);

Executes at least once.

LoopCondition CheckMinimum Execution
whileBefore0 times
do-whileAfter1 time

4Branching statements

  • break — exits the loop/switch immediately.
    • Labeled break (rarely used):
java — labeled break 
outer: for(int i=0; i<5; i++) {
    for(int j=0; j<5; j++) {
        if(condition) break outer;  // breaks outer loop
    }
}
  • continue — skips the rest of the current iteration, goes to the next. Labeled continue also exists.
  • return — exits the method entirely (not just the loop).

5Common interview questions

Q: Difference between break and continue?

break → exits the loop; continue → skips to the next iteration.

Q: Can we use floating-point in switch?

No, only integer-based or String/enum.

Q: Infinite loop examples?

for(;;) { }
while(true) { }

Q: Why is the enhanced for loop preferred?

Cleaner, less error-prone, avoids index out of bounds.

Q: Can we modify a collection in an enhanced for loop?

Throws ConcurrentModificationException if structurally modified.

Q: Nested switch allowed?

Yes, an inner switch can be inside a case block.

6Quick cheat sheet

StatementUse CaseKey Feature
if-elseSimple conditionsBasic branching
switchMultiple constant checksEnhanced version (Java 14+) preferred
forKnown iterationsFull control
for-eachArrays/collectionsRead-only, clean
whileCondition-based, unknown countCheck before
do-whileAt least one execution neededCheck after
02 · Methods & Constructors

Object-oriented programming: methods in Java

Definition, types, overloading, overriding, arguments, varargs, and recursion.

1What is a method?

  • A method is a block of code that performs a specific task and can be invoked (called) multiple times.
  • Methods promote code reusability, modularity, and better organization.

Syntax:

java 
modifier returnType methodName(parameterList) throws ExceptionList {
    // method body
    return value;  // if returnType is not void
}

2Components of a method

  • Modifiers — public, private, protected, static, final, abstract, synchronized, etc.
  • Return Type — the data type of the value returned (void if nothing is returned).
  • Method Name — follows identifier rules (camelCase convention).
  • Parameter List — zero or more parameters (type paramName).
  • Throws Clause — optional, declares checked exceptions.
  • Body — code inside {}.
java — example 
public int add(int a, int b) {
    return a + b;
}

3Types of methods

TypeDescriptionExample
Instance MethodBelongs to the object; can access instance variables & methodsobj.display()
Static MethodBelongs to the class; accessed using the class name; cannot access instance membersMath.max(10, 20)
Abstract MethodDeclared in an abstract class/interface; no body; must be overriddenabstract void draw();
Final MethodCannot be overridden in a subclassfinal void calculate()
ConstructorSpecial method to initialize objects (same name as class, no return type)public ClassName(int x) { ... }

4Method overloading

  • Multiple methods with the same name but different parameter lists (type, number, or order).
  • Return type alone cannot overload.
  • Compile-time polymorphism.
java — example 
void show(int a) { ... }
void show(String s) { ... }
void show(int a, double b) { ... }

Interview questions:

Q: Can we overload the main() method?

Yes.

Q: Difference between overloading and overriding?

Overloading: same class, different parameters. Overriding: different classes (inheritance), same signature.

5Method overriding

  • Subclass provides a specific implementation of a method already defined in the superclass.
  • Runtime polymorphism.

Rules:

  • Same name, return type, and parameters.
  • Access modifier cannot be more restrictive.
  • Cannot override static/final/private methods.
  • Can throw narrower or fewer exceptions.
  • Use the @Override annotation (recommended — catches errors at compile time).
java — example 
class Parent {
    void display() { System.out.println("Parent"); }
}

class Child extends Parent {
    @Override
    void display() { System.out.println("Child"); }
}

6Passing arguments

  • Pass-by-Value — Java always passes primitive and reference variables by value:
    • Primitives: copy of the value.
    • Objects: copy of the reference (changes to object fields affect the original).
java 
void modify(int x) { x = 50; }          // No effect on original
void modify(Student s) { s.name = "New"; }  // Affects original object

Common interview trap:

java 
void swap(int a, int b) {
    int temp = a; a = b; b = temp;
}
// Doesn't swap original variables – only copies

7Varargs (variable arguments) — Java 5+

  • Allows a method to accept zero or more arguments of the same type.
  • Syntax: type... parameterName
java 
void print(String... values) {
    for(String s : values) {
        System.out.println(s);
    }
}
// Call: print("A"), print("A","B","C"), print()

Rules:

  • Only one varargs per method.
  • Must be the last parameter.
  • Internally treated as an array.

8Recursion

  • A method calls itself.
  • Must have a base case to avoid StackOverflowError.
java 
int factorial(int n) {
    if (n == 0) return 1;
    return n * factorial(n-1);
}

9Key interview questions

Q: Can we change the return type in overriding?

No (except covariant return types — Java 5+ allows a subclass of the original return type).

Q: Static method overriding?

Not possible — it's method hiding.

Q: main() method — why public static void?

public → JVM can access; static → no object needed; void → no return to JVM.

Q: Can a constructor be final/static/abstract?

No.

Q: Difference between method hiding and overriding?

Static methods → hiding (resolved at compile time); instance → overriding (runtime).

10Quick summary table

FeatureOverloadingOverriding

PolymorphismCompile-timeRuntime

KeywordsN/A@Override (recommended)
02 · Methods & Constructors

Constructors

Initializing objects, types of constructors, chaining, and the Singleton pattern.

1What is a constructor?

  • Special member method used to initialize objects.
  • Automatically called when an object is created using new.

Key characteristics:

  • Same name as the class.
  • No return type (not even void).
  • Can be overloaded.
  • Can have access modifiers (public, private, protected, default).

2Types of constructors

TypeDescriptionExample
No-Arg (Default)Takes no parameters; initializes with default valuespublic ClassName() { }
ParameterizedAccepts parameters to initialize instance variablespublic ClassName(int x, String s) { }
PrivateUsed in the Singleton pattern or to prevent direct instantiationprivate ClassName() { }
Copy ConstructorNot built-in; manually defined to create a copy of an objectClassName(ClassName obj) { ... }
java — example 
class Student {
    int id;
    String name;

    // No-arg constructor
    Student() {
        id = 0;
        name = "Unknown";
    }

    // Parameterized constructor
    Student(int i, String n) {
        id = i;
        name = n;
    }
}

3Constructor overloading

  • Multiple constructors with different parameter lists.
  • Achieves compile-time polymorphism.
java 
Student() { }                          // No-arg
Student(int id) { this.id = id; }      // One param
Student(int id, String name) { ... }   // Two params

4Default constructor

  • If no constructor is defined in the class, Java provides a default no-arg constructor.
  • As soon as you define any constructor (even parameterized), the default constructor is not provided.
Interview tip: common question — "Will the compiler add a default constructor if I write a parameterized one?" → No.

5this() and super() in constructors

this()

Calls another constructor in the same class (constructor chaining). Must be the first statement.

java 
Student() {
    this(0, "Default");  // Calls parameterized constructor
}
Student(int id, String name) {
    this.id = id;
    this.name = name;
}

super()

Calls a superclass constructor. Implicitly called if not written (calls the no-arg super). Must be the first statement if explicitly used.

java 
class Child extends Parent {
    Child() {
        super();  // Calls Parent's no-arg constructor
    }
}
Key rule: either this() or super() can be used, but not both in the same constructor.

6Important rules & restrictions

  • Cannot be static, final, or abstract.
  • Cannot be called explicitly like a method (only via new or this()/super()).
  • Private constructors prevent inheritance and instantiation (used in Singleton).
  • Constructors can throw exceptions.

7Constructor vs method (common interview question)

FeatureConstructorMethod
NameSame as classAny name
Return TypeNoneCan have any (including void)
CalledAutomatically on newExplicitly
InheritanceNot inheritedCan be inherited/overridden
PurposeInitialize objectPerform operations

8Common interview questions

Q: Can we have a return statement in a constructor?

Yes, but only return; (no value). Used for early exit.

Q: What happens if the superclass has no no-arg constructor?

The subclass must explicitly call super(param); otherwise a compile error.

Q: Can a constructor be synchronized?

Yes, but rarely needed (the object is not fully created during construction).

Q: Order of execution in inheritance?

Superclass constructor → Subclass constructor (always).

Q: Can we overload constructors?

Yes. Can we override constructors? No (not inherited).

Q: What is constructor chaining?

Calling one constructor from another using this().

9Singleton pattern using a private constructor

java 
class Singleton {
    private static Singleton instance;

    private Singleton() { }  // Private constructor

    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}

10Quick revision points

  • No return type.
  • Default constructor auto-provided only if no constructor exists.
  • this() and super() must be the first statement.
  • Private constructors → design patterns (Singleton, factory).
  • Constructor body executes after the superclass constructor.
02 · Methods & Constructors

The this keyword

Referencing the current object, shadowing, chaining, and inner classes.

1What is the 'this' keyword?

  • this is a reference variable that refers to the current object in an instance method or constructor.
  • Automatically created by the JVM for every object.
  • Primarily used to differentiate between instance variables and parameters/local variables with the same name.

2Common uses of 'this'

Use CaseDescriptionExample Code
Access Instance VariablesResolves name conflicts between fields and parametersthis.name = name;
Invoke Current Class ConstructorConstructor chaining using this()this(1, "Default");
Invoke Current Class MethodExplicitly call another instance methodthis.methodA();
Pass Current Object as ArgumentPass this to another method or constructornew B(this);
Return Current ObjectReturn this from a method for method chainingreturn this;
java — method chaining 
Student setName(String name) {
    this.name = name;
    return this;  // Enables chaining: obj.setName("X").setAge(20);
}

3Key rules & restrictions

  • this cannot be used in static methods or static blocks → compile error ("non-static variable this cannot be referenced from a static context").
  • this() must be the first statement in a constructor.
  • Only one this() or super() call allowed per constructor.
  • this is final — cannot be reassigned.

4Common interview questions

Q: Can we use 'this' in a static method?

No. Static context belongs to the class, not the object. No current object exists.

Q: What is the difference between 'this' and 'this()'?

this → refers to the current object. this() → calls another constructor in the same class.

Q: When is the 'this' reference automatically passed?

The JVM implicitly passes this as the first parameter in non-static method calls. Example: obj.method() internally becomes method(obj).

Q: Can we explicitly pass 'this' in a static method call?

No. Compile error.

Q: What happens if you write 'this = null' inside a method?

Compile error — this is final and cannot be reassigned.

Q: Why use 'this' to call a method when it's optional?

Improves readability, especially in large methods or when chaining.

Q: Can 'this' be used to refer to superclass members?

No. Use super for superclass members. this always refers to the current class instance.

5Practical example (shadowing issue)

java 
class Employee {
    String name;  // Instance variable

    void setData(String name) {  // Parameter shadows instance variable
        name = name;    // Wrong! Assigns parameter to itself
        // this.name = name;  // Correct – assigns to instance variable
    }
}

6this in inner classes

To refer to the outer class instance from an inner class: OuterClass.this

java 
class Outer {
    void display() {
        class Inner {
            void show() {
                Outer.this.display();  // Access outer method
            }
        }
    }
}

this.variableNoN/AAccess shadowed fields
this.method()NoN/ACall instance method
this()Yes (constructor)YesConstructor chaining
return thisNoN/AMethod chaining

03 · OOP & Interfaces

Access modifiers

Visibility scopes, rules, and common use cases.

1Overview

Access modifiers control the visibility and accessibility of class members (fields, methods, constructors, nested classes) from other classes.

Java has 4 access modifiers:

ModifierVisibility ScopeCan be Applied To
publicAccessible from everywhere (any class, any package)Class, field, method, constructor
protectedAccessible within the same package + subclasses in other packages (via inheritance)Field, method, constructor
default (no keyword)Accessible only within the same packageClass, field, method, constructor
privateAccessible only within the same classField, method, constructor, nested class

2Detailed visibility table

ModifierSame ClassSame Package (Subclass)Same Package (Non-Subclass)Different Package (Subclass)Different Package (Non-Subclass)
publicYesYesYesYesYes
protectedYesYesYesYesNo
defaultYesYesYesNoNo
privateYesNoNoNoNo

3Key points & rules

  • Top-level classes: can only be public or default (package-private). Cannot be private or protected.
  • Nested/Inner classes: can have all 4 modifiers.
  • Constructors: can have any modifier (private → Singleton, factory patterns).
  • Interfaces:
    • Pre-Java 8: methods are implicitly public abstract.
    • Java 8+: default methods → public default, static methods → public static.
    • Java 9+: private methods allowed.
  • Interface members: variables are implicitly public static final.

4Common use cases

ModifierTypical Usage
publicAPI methods, classes meant for external use
protectedMembers intended for subclass extension (e.g., template methods)
defaultPackage-private helpers, internal implementation details
privateEncapsulation — hide fields, expose via getters/setters
java — example 
public class Parent {
    public int publicVar;
    protected int protectedVar;
    int defaultVar;         // package-private
    private int privateVar;

    public void publicMethod() { }
    protected void protectedMethod() { }
    void defaultMethod() { }
    private void privateMethod() { }
}

class Child extends Parent {
    void test() {
        publicVar = 1;       // OK
        protectedVar = 2;    // OK (inheritance)
        defaultVar = 3;      // OK if same package
        // privateVar = 4;   // Compile error
    }
}

5Common interview questions

Q: Can a subclass in a different package access protected members?

Yes, but only through inheritance (via this or super), not via another object of the parent class.

Parent p = new Parent();
// p.protectedVar;  // Compile error in different package
this.protectedVar;  // OK in subclass

Q: Why can't we use private/protected for top-level classes?

Top-level classes are meant to be compilation units. Private/protected would make them inaccessible outside their scope, defeating the purpose.

Q: What is the default access modifier if none is specified?

Package-private (default).

Q: Can a private method be overridden?

No. Private methods are not inherited → no overriding (a subclass can define a same-name method, but it's a new method).

Q: Can we reduce visibility while overriding?

No. An overriding method must have the same or broader access (e.g., protected → public OK; public → protected NOT allowed).

Q: What happens if a class is default and in a named package?

Only classes in the same package can access it.

Q: Best practice for fields?

Always private + public getters/setters (encapsulation).

03 · OOP & Interfaces

Inheritance

Code reuse through the "IS-A" relationship.

1What is inheritance?

  • Inheritance is a core OOP principle that allows a class (subclass/child) to inherit fields and methods from another class (superclass/parent).
  • Promotes code reusability and establishes an "IS-A" relationship.
  • Represented in UML with a solid line and hollow triangle arrow pointing to the superclass.

2Syntax

java 
class Parent {
    // fields and methods
}

class Child extends Parent {  // Child inherits from Parent
    // can add new fields/methods or override inherited ones
}
  • Java supports single inheritance only (one direct superclass).
  • All classes implicitly extend java.lang.Object (ultimate superclass).

3Key features

  • Subclass gets all non-private members of the superclass.
  • Subclass can:
    • Use inherited members as-is.
    • Override inherited methods.
    • Add new members.
  • Supports hierarchical inheritance (multiple levels).

4Accessing superclass members

  • super keyword:
    • super() → call superclass constructor (must be first statement).
    • super.variable → access a shadowed superclass field.
    • super.method() → call an overridden superclass method.
java — example 
class Animal {
    String name = "Generic Animal";

    void eat() {
        System.out.println("Animal eats");
    }
}

class Dog extends Animal {
    String name = "Dog";

    void display() {
        System.out.println(name);          // "Dog"
        System.out.println(super.name);    // "Generic Animal"
    }

    @Override
    void eat() {
        super.eat();                       // Call parent's eat
        System.out.println("Dog eats bones");
    }
}

5Types of inheritance supported in Java

TypeSupported?Notes
SingleYesOne class extends one class
MultipleNoNot allowed for classes (use interfaces)
MultilevelYesA → B → C
HierarchicalYesOne parent, multiple children
HybridYesCombination (via interfaces)

6Important rules & restrictions

  • final class: cannot be extended (final class A {} → no subclass).
  • final method: cannot be overridden.
  • private members: not inherited.
  • Constructors: not inherited, but can be called via super().
  • static members: inherited but not overridden (method hiding).

7Method overriding rules

  • Same name, return type, and parameters.
  • Cannot reduce visibility (e.g., public → protected not allowed).
  • Can throw fewer/narrower exceptions.
  • Use the @Override annotation (recommended — catches errors at compile time).
  • Covariant return types (Java 5+): a subclass can return a subtype of the parent's return type.

8Common interview questions

Q: Why is multiple inheritance not supported for classes?

To avoid the Diamond Problem (ambiguity when two parents have the same method). Solved via interfaces (default methods with explicit override).

Q: Can a constructor be inherited or overridden?

No to both.

Q: What is method hiding?

Static methods in a subclass with the same signature hide the superclass method (not overridden).

Q: Difference between inheritance and composition?

FeatureInheritance (IS-A)Composition (HAS-A)
RelationshipTight couplingLoose coupling
Code ReuseVia extensionVia delegation
FlexibilityLess (fixed hierarchy)More (can change at runtime)
ExampleDog extends AnimalCar has Engine

Q: When to prefer composition over inheritance?

When the relationship is HAS-A, or to avoid the fragile base class problem (GoF recommendation).

Q: Can a subclass access private members of the superclass?

No, not directly. Use protected or public getters/setters.

Q: What happens if the superclass doesn't have a no-arg constructor?

The subclass must explicitly call super(params).

10Quick summary

  • extends keyword for classes.
  • IS-A relationship.
  • Single inheritance only.
  • Use super to access parent members.
  • Prefer composition for flexibility.
  • @Override is best practice.

Aggregation in Java OOP

The "HAS-A" relationship and how it differs from composition.

1What is aggregation?

  • Aggregation is a "HAS-A" relationship between two classes where one class contains a reference to another class.
  • It represents a weak whole-part relationship: the part can exist independently of the whole.
  • The lifecycle of the contained object is not managed by the container — it can be shared or exist separately.
  • Modeled using a hollow diamond arrow in UML class diagrams (container → part).
FeatureAggregationComposition
Relationship StrengthWeak (part can live without whole)Strong (part dies with whole)
UML NotationHollow diamondFilled diamond
LifecycleIndependentDependent
ExampleCar HAS-A Driver (driver can exist alone)Car HAS-A Engine (engine rarely reused)
OwnershipNo strict ownershipContainer owns the part

2Implementation example

java 
class Address {
    String city;
    String street;

    public Address(String city, String street) {
        this.city = city;
        this.street = street;
    }
}

class Employee {
    private int id;
    private String name;
    private Address address;  // Aggregation: Employee HAS-A Address

    public Employee(int id, String name, Address address) {
        this.id = id;
        this.name = name;
        this.address = address;  // Reference to independent object
    }

    // Getter/Setters...
}

Usage:

java 
Address addr = new Address("New York", "5th Ave");  // Address exists independently
Employee emp1 = new Employee(1, "John", addr);
Employee emp2 = new Employee(2, "Jane", addr);     // Same Address shared (possible in aggregation)

3Key characteristics

  • No ownership: destroying the container (Employee) does not destroy the part (Address).
  • Parts can be shared among multiple containers.
  • Typically implemented via reference fields (not mandatory to nullify on container destruction).
  • Promotes reusability and loose coupling.

4Aggregation vs composition code difference

Aggregation (loose coupling):

java 
class Department {
    private List employees;  // Employees can belong to multiple depts or exist alone
}

Composition (tight coupling):

java 
class Car {
    private Engine engine;  // Engine created and managed by Car

    public Car() {
        this.engine = new Engine();  // Engine created inside Car
    }
    // When Car is garbage collected, Engine has no other references → destroyed
}

5Class diagram representation

uml
+-----------------+ | Employee | +-----------------+ | - id: int | | - name: String | | - address: Address +-----------------+ ◇──────────► +-----------------+ | Address | +-----------------+ | + city: String | | + street: String| +-----------------+
Note: the hollow diamond (◇) indicates aggregation.

6Common interview questions

Q: What is the difference between aggregation and composition?

Aggregation = weak HAS-A (independent lifecycle, hollow diamond); Composition = strong HAS-A (dependent lifecycle, filled diamond).

Q: Can aggregation have multiplicity?

Yes (e.g., 1 Department → * Employees).

Q: Is aggregation a type of association?

Yes — aggregation is a specialized form of association indicating whole-part.

Q: When to use aggregation over composition?

When the part can exist independently or be shared (e.g., Student-Course, Library-Book).

Q: In code, how do you distinguish aggregation from composition?

Purely by design intent and lifecycle management. Java has no keyword — it's a modeling concept. Composition usually creates the part internally.

Q: Can a class have both aggregation and composition?

Yes (e.g., University HAS-A Departments (aggregation) and HAS-A CampusBuilding (composition)).

7Quick summary

  • HAS-A relationship.
  • Weak association → independent existence.
  • Hollow diamond in UML.
  • No automatic lifecycle management.
  • Used for reusable, shareable components.

Interfaces

Contracts, evolution, marker & functional interfaces, and abstract classes.

1What is an interface?

  • An interface is a blueprint of a class that defines what a class must do (methods) but not how.
  • It is a contract: any class implementing it must provide implementations for its methods.
  • Supports abstraction and multiple inheritance (a class can implement multiple interfaces).
  • Declared using the interface keyword.
java 
public interface Drawable {
    void draw();  // implicitly public and abstract
}

2Key features

  • All methods are public abstract by default (pre-Java 8).
  • All variables are public static final (constants).
  • Cannot have constructors.
  • Cannot be instantiated directly.
  • A class implements an interface using implements.
  • An interface can extend one or more interfaces.

3Evolution of interfaces

Java VersionNew FeaturesExample
Pre-Java 8Only abstract methodsvoid method();
Java 8Default methods (with body)
Static methods		default void show() { ... }
static void util() { ... }
Java 9Private methods (for code reuse in default methods)private void helper() { ... }

4Implementation example

java 
interface Animal {
    void eat();  // abstract

    default void sleep() {  // Java 8+
        System.out.println("Sleeping...");
    }

    static void info() {    // Java 8+
        System.out.println("This is an Animal interface");
    }
}

class Dog implements Animal {
    public void eat() {     // Must be public
        System.out.println("Dog eats bones");
    }
    // sleep() inherited as-is
}

5Interface vs abstract class (most asked)

FeatureInterfaceAbstract Class
MethodsMostly abstract; default/static/private (Java 8+)Abstract or concrete
VariablesOnly public static finalAny (instance, static)
ConstructorsNoYes
InheritanceMultiple (implements multiple)Single only
Access ModifiersMethods implicitly publicAny (public, protected, etc.)
Extends/ImplementsCan extend multiple interfacesCan extend one class only
Use CaseDefine contract (e.g., Comparable, Runnable)Share code among related classes

6Marker interface

  • An interface with no methods or constants.
  • Used to tag a class (conveys metadata to the JVM or frameworks).
  • Examples: Serializable, Cloneable, Remote.
java 
interface MyMarker { }  // No members

class MyClass implements MyMarker { }

7Functional interface (Java 8+)

  • An interface with exactly one abstract method.
  • Can have default/static methods.
  • Annotated with @FunctionalInterface (optional but recommended — compile check).
  • Used with Lambda expressions.
java 
@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);  // Only one abstract method

    default void log() { }       // Allowed
}

Usage with Lambda:

java 
Calculator add = (a, b) -> a + b;
System.out.println(add.calculate(5, 3));  // 8

Common built-in functional interfaces: Runnable, Callable, Comparator, Predicate, Function, Consumer, etc.

8Common interview questions

Q: Why were default methods introduced in Java 8?

To add new methods to existing interfaces (e.g., List.sort()) without breaking implementing classes (backward compatibility — Lambda and Stream API support).

Q: Can we override a default method?

Yes, in an implementing class.

Q: What happens if two interfaces have the same default method?

The implementing class must explicitly override it (class wins over interface).

class MyClass implements Interface1, Interface2 {
    public void method() { Interface1.super.method(); }  // Resolve conflict
}

Q: Can an interface have private methods?

Yes (Java 9+), only for code reuse inside default methods.

Q: Can an interface be final?

No — interfaces are meant to be implemented.

Q: Can a class implement two interfaces with the same method signature?

Yes — one implementation satisfies both.

Q: Difference between interface and abstract class?

See the table above.

9Quick summary

  • Contract with public abstract methods.
  • Supports multiple inheritance.
  • Java 8+: default, static methods.
  • Java 9+: private methods.
  • @FunctionalInterface for lambdas.
  • Prefer interfaces for defining APIs/types.

The final keyword

Restricting modification across variables, methods, and classes.

1What is 'final'?

  • final is a non-access modifier that restricts further modification.
  • Can be applied to variables, methods, classes, and method parameters.
  • Once declared final, the value/behavior cannot be changed.

2Usage of final

Applied ToEffectExample
VariableBecomes a constant — value cannot be reassigned after initializationfinal int MAX = 100;
Instance VariableMust be initialized in the constructor or at declarationfinal String name; (initialized in ctor)
Static VariableClass-level constant (often with static)public static final double PI = 3.14159;
Method ParameterParameter value cannot be changed inside the methodvoid process(final int x)
MethodCannot be overridden in a subclassfinal void calculate()
ClassCannot be extended (no subclass allowed)final class String (real example)

3final variable rules

  • Local variable: must be initialized before use.
  • Instance/static variable: can be initialized at declaration, in an instance/static block, or in a constructor (for instance) / static block (for static).
  • Once initialized, cannot be reassigned.
  • Blank final variable: declared final but not initialized at declaration — must be initialized in the constructor.
java — example 
class Example {
    final int instanceFinal;          // Blank final
    static final int STATIC_FINAL;    // Blank static final

    static {
        STATIC_FINAL = 100;           // Initialized in static block
    }

    Example() {
        instanceFinal = 200;          // Initialized in constructor
    }
}

4final method

  • Prevents overriding in subclasses.
  • Useful for security, design (template methods), or performance (inlining possible).
java 
class Parent {
    final void doNotOverride() {
        System.out.println("Cannot override");
    }
}

class Child extends Parent {
    // void doNotOverride() { }  // Compile error
}

5final class

  • Cannot be subclassed.
  • Examples in the JDK: String, Integer, Double, System, Math (some methods final).
java 
final class MyFinalClass { }
// class Sub extends MyFinalClass { }  // Compile error

6Common interview questions

Q: Can a final variable be reassigned?

No, once initialized.

Q: What is the difference between final, finally, and finalize()?

KeywordPurposeContext
finalMakes variable/method/class immutable/unextendableCompile-time restriction
finallyBlock that always executes after try-catchException handling
finalize()Deprecated method called before GCObject cleanup (avoid using)

Q: Can we declare a constructor as final?

No — constructors cannot be final, static, or abstract.

Q: Can a final method be overloaded?

Yes (overloading is same class, different parameters).

Q: What happens if a blank final variable is not initialized?

Compile error.

Q: Why is the String class final?

For immutability, security (used in class loading, permissions), thread-safety, and string pool optimization.

Q: Can we change the value of a final object reference?

No — the reference cannot point to another object, but the object's internal state can change if it is not immutable.

final List list = new ArrayList<>();
list.add("New");        // Allowed – object state changes
// list = new ArrayList<>();  // Compile error

Q: Performance benefit of final?

The JVM can inline final methods/variables — a slight optimization.

Q: Can local variables be declared final?

Yes — useful in anonymous inner classes (pre-Java 8 for effective final).

7Best practices

  • Use final for constants: public static final.
  • Make classes final if not designed for inheritance.
  • Make methods final if not intended for overriding.
  • Prefer immutability (combine with private fields).

Objects and wrapper classes

Primitives as objects, autoboxing, caching, and the == vs equals() gotcha.

1Everything is NOT an object

  • Java is not purely object-oriented because primitives (int, boolean, etc.) are not objects.
  • Primitives are stored directly in memory (stack) for performance.
  • To treat primitives as objects, Java provides Wrapper Classes.

2Wrapper classes

  • Wrapper classes provide an object representation of primitive data types.
  • Located in the java.lang package (auto-imported).
  • All are final and immutable.
Primitive TypeWrapper ClassDefault Value (as Object)
byteBytenull
shortShortnull
intIntegernull
longLongnull

doubleDoublenull

booleanBooleannull

3Key features

  • Immutable: once created, the value cannot be changed.
  • Useful for:
    • Collections (List<Integer>, Map<String, Integer> — cannot store primitives).
    • Generics.
    • Methods that require objects (e.g., Object as a parameter).

4Autoboxing and unboxing (Java 5+)

  • Autoboxing: automatic conversion from primitive → wrapper object.
  • Unboxing: automatic conversion from wrapper object → primitive.
java — examples 
Integer obj = 10;              // Autoboxing (int → Integer)
int num = obj;                 // Unboxing (Integer → int)

List list = new ArrayList<>();
list.add(5);                   // Autoboxing: 5 → new Integer(5)

int sum = obj + 20;            // Unboxing: obj → int, then add

5Common methods (Integer as an example)

java 
Integer.parseInt("123");       // String → int
Integer.valueOf("123");        // String → Integer (preferred, cached)
Integer.toString(123);         // int → String
Integer.compare(10, 20);       // Returns -1, 0, 1
Integer.MAX_VALUE              // 2147483647
Integer.MIN_VALUE              // -2147483648

6Caching in wrapper classes (important for interviews)

  • Integer: caches values from -128 to 127 (default range).
java 
Integer a = 100;
Integer b = 100;
System.out.println(a == b);  // true (same cached object)

Integer c = 200;
Integer d = 200;
System.out.println(c == d);  // false (new objects created)
  • Can be changed with the JVM option: XX:AutoBoxCacheMax=<size>
  • Other wrappers:
    • Byte, Short, Long: -128 to 127
    • Character: 0 to 127
    • Boolean: true/false always cached
    • Float/Double: no caching

Interview gotcha:

java 
Integer x = 400;
Integer y = 400;
System.out.println(x == y);     // false (no caching beyond 127)
System.out.println(x.equals(y)); // true (value comparison)

7Common interview questions

Q: Why do we need wrapper classes?

To use primitives in collections, generics, and methods expecting Object.

Q: Difference between == and equals() in wrapper classes?

== → compares object references (same object?). equals() → compares actual values.

Q: What is autoboxing/unboxing? Give the performance impact.

Convenient but creates temporary objects → slight performance overhead (avoid in tight loops).

Q: Can we extend wrapper classes?

No — all are final.

Q: When does Integer caching apply?

Only -128 to 127 by default, and only with autoboxing (not with new Integer()).

Q: Why a null pointer exception in unboxing?

Integer obj = null;
int value = obj;  // NullPointerException (auto-unboxing null)

Q: Best way to convert String to int?

Integer.parseInt(str) (returns primitive) or Integer.valueOf(str) (returns Integer, better caching).

3Garbage collection (GC)

  • Automatic memory reclamation of objects no longer referenced.
  • Eligibility: an object has no active references (null or out of scope).
  • How GC works:
    1. Mark Phase: identifies reachable (live) objects from roots (stack, static vars, etc.).
    2. Sweep/Compact Phase: reclaims memory of unmarked objects; may compact to reduce fragmentation.
