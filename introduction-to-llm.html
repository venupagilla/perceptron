Lec 03 Introduction to Statistical Language Models

Statistical n-gram language models: the chain rule, the Markov assumption, and their limitations.

How Does It Work?

Using the Chain Rule:

\[P(\text{I love ice cream}) = P(\text{I}) \times P(\text{love} \mid \text{I}) \times P(\text{ice} \mid \text{love}) \times P(\text{cream} \mid \text{ice})\]
  • Learned from huge collections of text (a corpus).
Chain Rule Decomposition
flowchart LR
    P["P(I love ice cream)"] --> P1["P(I)"]
    P --> P2["P(love | I)"]
    P --> P3["P(ice | love)"]
    P --> P4["P(cream | ice)"]
    P1 & P2 & P3 & P4 --> M["Chain Rule
multiply all probabilities"]

The Big Trick: Markov Assumption

Next word depends only on the last few words.

Building a Model

  1. Count words in a big text collection.
  2. Make a probability table: P = Count("I love") / Count("I")
  3. Problem: Sparsity — most combinations never appear → Probability = 0!

Fixing the Problems

  • OOV words: Replace rare words with <UNK>.
  • Smoothing: "Add a little fake count."
  • Add-One (Laplace): Add 1 to every count.
  • Backoff: If trigram fails, fall back to bigram, then unigram.
  • Interpolation: Mix all levels with weights.

Why It's Still Limited

  • Only remembers a few previous words.
  • Needs tons of data.
  • Doesn't truly "understand" meaning — just patterns.

Lec 04 Statistical LM: Advanced Smoothing and Evaluation

How to make statistical models smarter with new/rare word combinations and how to evaluate them.

Main Problems Fixed

  1. Add-One/Laplace smoothing is too simple — over-boosts rare words.
  2. Need better ways to handle unseen/rare pairs.

Advanced Smoothing Techniques

  • Good-Turing Smoothing: Uses "frequency of frequencies" (Nc) to estimate probability of unseen items.
  • Absolute Discounting + Interpolation: Subtract a fixed discount D (e.g., 0.75) from seen pairs, redistribute to unseen; mix with simpler models.
  • Kneser-Ney Smoothing: Uses continuation probability — how many different contexts a word appears in (e.g., "coffee" has high continuation vs. "Los" which mostly precedes "Angeles").

Evaluation

  1. Extrinsic Evaluation: Use the model in a real task (e.g., translation, measured by BLEU). Practical but slow/expensive.
  2. Intrinsic Evaluation → Perplexity (PP):
    • Measures how "surprised" the model is by new sentences.
    • PP = 2 raised to (average surprise per word).
    • Lower PP = better model.
    • Connected to entropy.

Quick Summary

  • Statistical LMs = big tables of word-pair probabilities + smoothing tricks.
  • Good-Turing, Kneser-Ney → smarter than simple +1.
  • Perplexity = "How confused is my model?" Lower = smarter.

Lec 06 Introduction to PyTorch

PyTorch is the main library used to build and train neural networks — the "toolbox" for LLMs.

Core Concepts

  1. Tensors: The main data type (scalars, vectors, matrices, higher dimensions). Key properties: shape, dimension, dtype, device (CPU/GPU). Operations: element-wise math, indexing/slicing, reshape, view.
  2. Autograd: Automatic gradient computation.
    • requires_grad=True on trainable tensors.
    • Builds a computation graph automatically.
    • .backward() computes gradients; .grad shows them.
    • torch.no_grad() disables tracking (for inference).
  3. Full Training Pipeline:
    1. Forward pass: Input → model → prediction.
    2. Compute loss (MSE, Cross-Entropy).
    3. Backward pass: .backward().
    4. Update weights: Optimizer (SGD, Adam): weight -= learning_rate * gradient.
  4. Real Example: MNIST Classifier — torchvision, DataLoader, nn.Module, train loop with epochs, Adam optimizer, Cross-Entropy loss → ~97% accuracy.

Lec 07 Word Representation: Word2Vec & fastText

1. Why Do We Need Word Representation?

Computers understand numbers, not words. Simple flawed solutions:

  • ASCII Values: variable length, no semantics.
  • One-Hot Encoding: no similarity (dot product always 0), curse of dimensionality, sparsity.

2. WordNet (Traditional Semantic Resource)

  • Manually created ontology with Synsets (synonym sets) and Glosses (definitions), linked via hypernymy, hyponymy, meronymy, etc.
  • Problems: incomplete, subjective/labor-intensive, limited coverage, discrete (not continuous vectors).

3. Distributional Semantics

Core Philosophy

"You shall know a word by the company it keeps." (J.R. Firth, 1957) — Words in similar contexts have similar meanings.

4. Count-Based Methods

4.1 Term-Context Matrix

Rows = target words, columns = context words, cell = co-occurrence count. Problem: high-dimensional, sparse; stop words dominate.

4.2 TF-IDF

\[\begin{aligned} \text{TF}(t,d) &= \log(\text{count}(t,d) + 1) \\ \text{IDF}(t) &= \log(N / \text{DF}(t)) \\ \text{TF-IDF}(t,d) &= \text{TF}(t,d) \times \text{IDF}(t) \end{aligned}\]

Still: sparse, no word order, needs matrix rebuild for new words.

5. Prediction-Based Methods: Word2Vec (Mikolov et al., 2013)

Train a simple neural network to predict co-occurrences → dense, low-dimensional embeddings.

Two Architectures

CBOW vs Skip-gram
flowchart LR
    subgraph CBOW["CBOW: predict target from context"]
        C1["context: 'the ___ sat'"] --> CT["target: 'cat'"]
    end
    subgraph SG["Skip-gram: predict context from target"]

Skip-gram with Negative Sampling

  1. Sliding window creates positive pairs (w, c_pos); random negative sampling creates (w, c_neg).
  2. Maintain target matrix and context matrix (size |V| x d).
  3. \(P(\text{positive}|w,c) = \sigma(c\cdot w) = \dfrac{1}{1+e^{-c\cdot w}}\).
\[L = -\left[\log\sigma(c_{\text{pos}}\cdot w) + \sum_i \log\sigma(-c_{\text{neg},i}\cdot w)\right]\]
  1. Gradient descent moves positive pairs closer, negative pairs farther apart.
  2. Final embedding = sum of target + context vectors.

Tricks

  • Negative sampling distribution: \(P(w) = \dfrac{\text{count}(w)^{0.75}}{\sum_w \text{count}(w)^{0.75}}\)
  • Subsampling frequent words: \(P(\text{keep}(w)) \approx \sqrt{t/f(w)}\)

Properties & Limitations

Properties: Dense, low-dimensional; semantic regularity (king - man + woman ≈ queen).

Limitations: Static embeddings (one vector per word regardless of context), OOV problem.

6. fastText (Facebook)

  • Extension of Skip-gram; represents a word as a bag of character n-grams.
  • Example: "where" (n=3) → <wh, whe, her, ere, re> plus <where>.
  • Final embedding = sum of vectors of all n-grams.
  • Advantages: Handles OOV words, captures morphology.

Lec 08 Word Representation: GloVe

What is GloVe?

GloVe = Global Vectors for Word Representation. Unsupervised algorithm from Stanford (2014), combining strengths of count-based and prediction-based methods.

Core Idea

Ratios of word-word co-occurrence probabilities encode meaning better than raw probabilities.

Example ("ice" vs "steam"):

Probabilitysolidgaswaterfashion
P(k|ice)0.000190.0000660.0030.000017
P(k|steam)0.0000220.000780.00220.000018
Ratio8.90.0851.360.96
  • Ratio > 1 → related to "ice"; Ratio < 1 → related to "steam"; Ratio ≈ 1 → related to both/neither.

How GloVe Works

  1. Co-occurrence Matrix X: X_ij = how often word j appears in context of word i (with distance-based weighting).
  2. Training Objective: \(w_i^\top \tilde{w}_j + b_i + \tilde{b}_j = \log(X_{ij})\)
  3. Loss Function: \(J = \sum_{ij} f(X_{ij})\big(w_i^\top \tilde{w}_j + b_i + \tilde{b}_j - \log X_{ij}\big)^2\) — with \(f(x) = (x/100)^{0.75}\) if \(x<100\), else 1. Non-decreasing, capped, zero for \(X_{ij}=0\).
  4. Final Vector = sum of center and context vectors.

GloVe vs Word2Vec

AspectWord2VecGloVe
Core ApproachPrediction-basedCount-based + Matrix Factorization
Training DataLocal context windowsGlobal co-occurrence statistics
ObjectiveMaximize probability of context wordsMinimize dot product vs log co-occurrence difference
ResultDense vectorsDense vectors, excellent linear structure

Advantages

  • Linear substructures (analogy tasks): king - man + woman ≈ queen.
  • Efficient training (uses only non-zero entries).
  • Captures global statistics.

Limitations

  • Static embeddings (one vector per word).
  • OOV words unrepresented.
  • Computational cost for co-occurrence matrix.

Recent Updates (2024–2025)

Stanford released updated 2024 GloVe vectors (July 2025) trained on Wikipedia (2024), Gigaword 5, Dolma subset (220B tokens) — includes newer vocabulary like "covid."

When to Use GloVe

Low-resource settings, interpretability-focused applications, baselines, quick prototyping.

1. Why Tokenization Matters

Models take sequences of tokens as input. Question: what constitutes a "token"?

Two components: Token Learner (training time, builds vocabulary) and Token Segmenter (test time, splits new text).

3. Byte Pair Encoding (BPE)

Used in: GPT, GPT-2, RoBERTa, BART. Originally a compression algorithm (1990s), adapted for NLP in 2016.

Core Philosophy: Start with base vocabulary (characters), iteratively merge most frequent adjacent pair, increasing vocab size.

  • Token Learner Steps:
    1. Pre-tokenization: clean & split corpus into words, record frequencies.
    2. Base vocabulary: all unique characters.
    3. Iterative merging: count adjacent pair frequencies, merge highest-frequency pair, record merge rule, repeat until target vocab size.
  • Token Segmenter: Split word into characters, apply merge rules in learned order. Unknown characters → <unk>. (Modern BPE, e.g. GPT-2, uses bytes as base vocabulary to avoid <unk>.)

4. WordPiece

Used in: BERT, DistilBERT, MobileBERT, MPNet.

  • Similar to BPE but merges based on a likelihood score: Score = freq(pair) / (freq(first) × freq(second)) (PMI-like).
  • Uses ## prefix to indicate non-start-of-word tokens (e.g., "hello" → h, ##e, ##l, ##l, ##o).
  • Token Segmenter: Greedy Longest-Match-First — no merge rules stored, only final vocabulary.
  • Unknown handling: if any character is missing from vocab, the entire word becomes <unk>.

5. Unigram Language Model Tokenization (SentencePiece)

Used in: T5, ALBERT, XLNet.

  • Opposite direction: start with a huge vocabulary, iteratively prune least useful tokens.
  • Based on Unigram LM: P(sequence) = P(t1) × P(t2) × ... × P(tn).
  • Uses Expectation-Maximization (EM) and Viterbi algorithm to find best segmentation.
  • Token Learner: build huge initial vocab → estimate probabilities → find best segmentation per word → calculate corpus loss → test removing each token (least loss-increasing tokens are pruned) → repeat until target size.
  • Token Segmenter: finds most probable segmentation via Viterbi.

7. Why Tokenization Matters for Low-Resource Languages

Subword tokenization helps because character n-grams may overlap across related languages, even without direct training data.

8. Key Takeaways

  1. Tokenization is the first step in any NLP pipeline.
  2. Subword tokenization is the standard approach.
  3. BPE = frequency-based; WordPiece = likelihood-score-based; Unigram LM = probability-based pruning.
  4. Tokenizer choice affects performance on rare words and morphologically rich languages.

Lec 10 Neural Language Models: CNN & RNN

1. Recap: Statistical LM Problems

Unknown words, sparsity, no generalization.

2. Introduction to Neural Language Models

  • Pioneer: Yoshua Bengio (2001–2002) — first neural LM using distributed representations.
  • Advantages: no sparse matrices, generalizes via embeddings, can handle unknown words (with subwords).

3. CNN-Based Neural Language Model

From 2D images to 1D text: window of words → concatenate embeddings → linear layer → hidden state → linear layer → vocab-size logits → softmax.

Detailed walkthrough (window=4): h = σ(W · concat(x1,x2,x3,x4) + b), z = U·h, P(w_next|context) = softmax(z).

4. Recurrent Neural Networks (RNN)

Maintains a hidden state updated sequentially: \(h_t = \sigma(W_{hh}\, h_{t-1} + W_{xh}\, x_t + b)\)

  1. Variable-length context (theoretically retains all history).

Lec 11 Neural Language Models: LSTM & GRU

The Core Problem — "Telephone Game" Analogy

Vanilla RNN = telephone game: each step distorts information; after many steps, the original message is lost (vanishing gradient).

LSTM = each step writes to a whiteboard (cell state) carried forward — can erase (forget gate), add (input gate), read (output gate).

LSTM (Long Short-Term Memory)

At each timestep t, LSTM maintains two states:

StateSymbolPurpose
Hidden Stateh(t)Output at this timestep
Cell Statec(t)Long-term memory ("conveyor belt")

Three Gates (vectors of values between 0 and 1):

GateSymbolFunction
Forget Gatef(t)What to erase from memory
Input Gatei(t)What new info to add
Output Gateo(t)What to output
LSTM Cell Flow (timestep t)

Why LSTM solves vanishing gradient: \(\partial c_t / \partial c_{t-1} = f_t\). If \(f_t = 1\), gradient doesn't shrink — acts as a "highway" for gradients across hundreds of timesteps.

GRU Gates:

  • Reset Gate (r(t)): how much of past to ignore.
  • Update Gate (z(t)): how much of past to keep vs. add new.
\[\begin{aligned} z_t &= \sigma(W_z \cdot [h_{t-1}, x_t]) & \text{(update gate)}\\ r_t &= \sigma(W_r \cdot [h_{t-1}, x_t]) & \text{(reset gate)}\\ \tilde{h}_t &= \tanh(W_h \cdot [r_t \times h_{t-1}, x_t])\\ h_t &= (1-z_t) \times h_{t-1} + z_t \times \tilde{h}_t \end{aligned}\]

    G --> GRU2
Rule of thumb

Start with LSTM (more data) → switch to GRU for efficiency/less data.

Related Concepts

  • Bidirectional RNN: Two RNNs in opposite directions, concatenated — used when full sequence is available (not for generation).
  • Residual/Skip Connections: \(\text{output} = f(x) + x\) — keeps original info alive in deep networks.
  • Stacked (Multi-layer) RNNs: each layer's input is the previous layer's hidden state.

Common Misconceptions

  • Gates are NOT binary — they're continuous (0 to 1).
  • LSTM only reduces vanishing gradient, doesn't completely solve it.
  • GRU isn't always worse — often comparable and faster.
  • Cell state ≠ hidden state (cell = memory, hidden = output).

Lec 12 Sequence-to-Sequence Models

1. Introduction to Seq2Seq

  • Input sequence → output sequence.
  • Applications: Machine Translation, Summarization, Dialogue Systems, Image Captioning.
  • Uses two RNNs: Encoder (processes input) and Decoder (generates output).

2. Encoder-Decoder Architecture

  1. Encoder reads input sequence.
  2. Final hidden state passed to decoder.
  3. Decoder generates output token by token.

Training: Loss at each decoder timestep, summed/normalized; Backpropagation Through Time updates both encoder and decoder.

3. Teacher Forcing

Feed the actual ground-truth token (not the model's own prediction) into the decoder during training — makes training more stable. During inference, model must use its own predictions.

4. Seq2Seq as Conditional Language Model

\[P(Y|X) = P(y_1|X) \times P(y_2|X,y_1) \times \cdots \times P(y_T|X,y_1,\dots,y_{T-1})\]

5. Decoding Strategies (Inference)

  • A. Greedy Decoding: pick highest-probability token each step. No backtracking.
  • B. Exhaustive Search: consider all tokens at each step — V^T complexity, infeasible.
  • C. Beam Search: keep top K hypotheses at each step. Score = sum of log probabilities; normalize by sequence length to avoid bias toward shorter sequences.

  • Hypothesis: each potential translation path in beam search.
  • End-to-End Training: backpropagate through entire network.
  • Encoder has W_h, W_e (no output matrix U); Decoder additionally has U for vocab projection.

3. Stochastic Strategies

  • A. Random Sampling: sample from full distribution — too noisy, unreliable.
  • B. Top-K Sampling: select top K tokens, renormalize, sample. Limitation: optimal K varies by distribution shape.
  • C. Top-P (Nucleus) Sampling: select smallest set of tokens whose cumulative probability ≥ threshold P, renormalize, sample. Adapts dynamically to distribution shape.
  • D. Temperature Sampling: adjusts distribution sharpness via τ before sampling.
\[P(w_i) = \frac{\exp(\text{logit}_i / \tau)}{\sum_j \exp(\text{logit}_j / \tau)}\]
  • Low τ (e.g. 0.1): peaked, deterministic, repetitive.
  • High τ (e.g. 10): more uniform, creative, diverse.
  • τ=1: standard softmax.

Lec 14 Attention in Sequence-to-Sequence Models

1. Limitations of Basic Seq2Seq

  1. No Parallelization: RNNs process sequentially.
  2. Linear Interaction Distance: hard to capture long-range dependencies.
  3. The Bottleneck Problem: entire input compressed into a single final hidden-state vector.

2. Core Idea of Attention

Direct connection from decoder to all encoder hidden states — decoder "attends to" the most relevant input parts, creating a shortcut for information flow.

3. How Attention Works (Vanilla Dot-Product Attention)

  • Query (Q): current decoder hidden state (s(t)).
  • Keys (K) / Values (V): encoder hidden states (h1...hn).
Attention Mechanism
flowchart LR
    Q["Query s(t)
decoder hidden state"] --> S["Attention Scores
Score(s(t),h(i)) = s(t).h(i)"]
    K["Keys/Values h1..hn
encoder hidden states"] --> S
    S --> W["Attention Weights
softmax gives alpha(t,i)"]
    W --> C["Context Vector
a(t) = sum alpha(t,i).h(i)"]
    C --> O["Combine & generate
concat(s(t), a(t)) to linear
to output token"]
  1. Attention Scores: \(\text{Score}(s_t,h_i) = s_t \cdot h_i\) (dot product).
  2. Attention Weights: softmax over scores → \(\alpha_{t,i}\).
  3. Context Vector: \(a_t = \sum_i \alpha_{t,i}\, h_i\) (weighted sum).
  4. Combine & Generate: concatenate s(t) and a(t), pass through linear layer to produce output token.

4. Advantages

AdvantageExplanation
Solves BottleneckDecoder accesses all encoder states, not just the final one
Mitigates Vanishing GradientShortcut path for gradients (like skip connections)
InterpretabilityAttention weights show input-output alignment
No Additional ParametersVanilla form adds no new trainable parameters

5. Attention as a General Concept

Query, Keys, Values → summary vector; squashes variable-length sequence into fixed-length context vector.

6. Variations of Attention

VariationFormulaNotes
Dot-Product\(\text{score} = Q \cdot K\)No parameters
Multiplicative (Bilinear)\(\text{score} = Q^\top W K\)Learnable projection matrix W
Additive (Concatenation)\(\text{score} = v^\top \tanh(W[Q;K])\)More computationally expensive
Scaled Dot-Product\(\text{score} = Q \cdot K / \sqrt{d_k}\)Used in Transformer, prevents vanishing gradients in softmax

7. Key Takeaways

  • Attention solves the bottleneck problem in Seq2Seq.
  • Creates a shortcut connection from every decoder step to every encoder state.
  • Provides interpretability via alignment.
  • General mechanism (Q, K, V) applicable beyond Seq2Seq.
  • Leads into: Self-Attention and the Transformer model.

Lec 15 Introduction to Transformers

Week 6 — The architecture behind modern LLMs. (Supplemented from the course syllabus; not in the original notes.)

Motivation: Why Not RNNs?

  • RNNs process tokens sequentially — one step must finish before the next starts. No parallelization across positions.
  • Long-range dependencies are hard to capture (vanishing gradients; even LSTM only reduces the problem).
  • Seq2Seq models compress the whole input into a fixed vector (the bottleneck problem).

The Transformer Architecture (Vaswani et al., 2017)

  • Replaces recurrence with self-attention: every token attends to every other token, all positions processed in parallel.
  • Core blocks: Multi-Head Self-Attention → Feed-Forward Network, wrapped with residual connections and layer normalization.
  • Positional encoding is added because self-attention has no built-in notion of order.
  • Two stacks: an encoder (bidirectional context) and a decoder (masked self-attention + cross-attention to the encoder).
  • The decoder-only variant (GPT-style) uses only the decoder stack with causal masking.
Transformer Block

(residual + layer norm)"]
    FD --> OUT["Output to next block"]
    IN -.->|"residual"| AD
    AD -.->|"residual"| FD

Why It Wins

PropertyRNNTransformer
ParallelizationSequentialFull parallel
Interaction distanceO(length) steps apartO(1) — direct attention
Training speedSlowMuch faster (GPU-friendly)
Long-range contextVanishing gradientDirect, but O(n²) compute

Cost: self-attention is O(n²) in sequence length — quadratic memory/compute, motivating later efficiency research.

Lec 16 Self and Multi-Head Attention

Week 6 — How attention becomes self-attention, and why multiple heads help. (Supplemented from the course syllabus.)

1. From Seq2Seq Attention to Self-Attention

  • In Seq2Seq, the decoder query attends to encoder keys/values (cross-attention).
  • In self-attention, the query, key, and value all come from the same sequence — every token attends to every other token (including itself).
  • Each token's representation becomes a contextualized mix of the whole sequence.

2. Scaled Dot-Product Attention

\[\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{Q K^\top}{\sqrt{d_k}}\right) V\]
Scaled Dot-Product Attention
flowchart LR

scoring"]

    C --> OUT["Context vectors

  • Why scale by √dₖ: dot products grow large with dₖ, pushing softmax into flat gradients (vanishing). Dividing keeps gradients healthy.
  • Interpretation: rows of the softmax matrix = how much each token attends to each other token.

3. Multi-Head Attention

Instead of one attention operation, run h parallel attention "heads" on projected Q/K/V, then concatenate the outputs.

  • Each head learns to attend to different relationship types (syntax, co-reference, positions, etc.).
  • Mathematically: \(\text{MultiHead}(Q,K,V) = \text{Concat}(\text{head}_1,\dots,\text{head}_h) \cdot W^O\), where each \(\text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V)\).
  • BERT-Base: 12 heads; BERT-Large: 16 heads.

Takeaway: attention = content-based routing; multiple heads = multiple simultaneous views of the same sequence.

Lec 17 Positional Encoding and Layer Normalization

Week 6 — Giving order to a permutation-invariant mechanism. (Supplemented from the course syllabus.)

1. Why Position Matters

Self-attention is permutation-invariant: shuffle the input tokens and attention produces the same result. Word order is essential to meaning ("dog bites man" ≠ "man bites dog"), so we must inject position information.

2. Sinusoidal Positional Encoding

\[\begin{aligned} \text{PE}(pos, 2i) &= \sin\!\left(pos / 10000^{2i/d}\right) \\ \text{PE}(pos, 2i+1) &= \cos\!\left(pos / 10000^{2i/d}\right) \end{aligned}\]
  • Each dimension of the position vector oscillates at a different frequency.
  • Advantages: no learned parameters, can extrapolate to unseen lengths, and relative offsets are expressible via linear combinations of sines/cosines.
  • Added to the token embeddings before the first block.
Adding Positional Encoding

    E["Token embeddings"] --> SUM["+"]
    P["Positional encoding

    SUM --> IN["Input to first
Transformer block"]

3. Alternatives

MethodUsed inNotes
Sinusoidal (fixed)Original TransformerNo parameters, extrapolates
Learned embeddingsBERT, GPTLearned per absolute position
RoPE (Rotary)LLaMA, GPT-NeoXRotates pairs of features; relative positions via rotation
ALiBiBLOOM, MPTAdds a bias scaled by distance

4. Layer Normalization

  • Normalizes across features for each token (mean 0, variance 1), then applies learned scale γ and shift β.
  • Unlike BatchNorm, it does not depend on batch statistics — works for variable-length sequences and during inference.
  • Placed around sub-layers (pre-norm: before attention/FFN; post-norm: after, as in original paper).
  • Together with residual connections (output = f(x) + x), it stabilizes deep transformer training.

Recipe for training deep transformers: self-attention + feed-forward, each wrapped in residual connection and layer norm, repeated L times.

Lec 18 Pre-Training Strategies: ELMo, BERT

Motivation for Contextualized Embeddings

Traditional embeddings (Word2Vec, GloVe) are static/context-independent — a word like "bat" gets the same vector regardless of usage. Modern strategies make embeddings dynamic based on context.

ELMo (Embeddings from Language Models, 2018)

Non-transformer approach creating deeply contextualized representations.

  • Architecture: Stacked bidirectional RNN (LSTM/GRU) — left-to-right + right-to-left, two layers each.
  • Embeddings as Hidden States: top-layer representations from forward and backward RNNs concatenated.
  • Pre-training Objective: language modeling (predict next word).
  • Tokenization: character-level CNN representations (solves OOV problem).
  • Task Adaptation: task-specific parameters (gamma) combine pre-trained hidden states.

The Paradigm Shift in Pre-Training

Shift from pre-trained word vectors (only input embeddings pre-trained/frozen) to pre-trained models (all internal parameters pre-trained then fine-tuned).

Three categories of Transformer pre-training:

  1. Decoder-only: GPT series.
  2. Encoder-only: BERT, ALBERT, RoBERTa.
  3. Encoder-Decoder: T5, BART.

BERT (Bidirectional Encoder Representations from Transformers)

Google's encoder-only transformer — bidirectional (no masked self-attention).

1. Pre-Training Objectives

BERT Pre-training Objectives

  • Masked Language Model (MLM): 15% of tokens selected; 80% → [MASK], 10% → random word, 10% → unchanged.
  • Next Sentence Prediction (NSP): predicts if two sentences are consecutive (50% positive/50% negative shuffled samples).

2. Special Tokens

  • [SEP]: separates two sequences.
  • [CLS]: prepended to sequence start, aggregates whole-input meaning for classification (unbiased toward specific tokens, fewer parameters needed).
  • Input = token encoding + position encoding + segment encoding.

3. Training Details

  • Trained on 2.5B word Wikipedia + 800M word Book corpus.
  • BERT-Base: 12 encoder layers, 12 attention heads.
  • BERT-Large: 24 encoder layers, 16 attention heads.

Fine-Tuning BERT (e.g., closed-book QA / SQuAD)

Question + passage fed together separated by [SEP]. Two classification heads predict start/end probability of the answer span per token. Inference finds (i,j) maximizing P_beginning × P_end where j ≥ i.

Legacy and Impact

BERT outperformed GPT-1, remained SOTA benchmark until 2020. Sparked TinyBERT, D-BERT (compressed) and RoBERTa (showed original BERT was undertrained).

T5 (Text-to-Text Transfer Transformer)

  • Maps every NLP problem to text-to-text using task prefixes, e.g., "translate English to German: [sentence]", "summarize: [document]".

Lec 21 Instruction Tuning

Source: YouTube — Lec 21 | Instruction Tuning

1. Background: Pre-trained Language Models (Base Models)

  • Base models are trained via next-word prediction on vast internet text.
  • They encode world knowledge but often just continue a prompt rather than answering it (e.g., asked "What is the national flower of India?" might generate "What is the national animal of India?" since such question lists are common online).
  • Next-word prediction alone doesn't ensure instruction-following.

2. Problem with Classical Multitask Learning

  • Model trained on multiple tasks via input-output examples but with no explicit task description.
  • Fails to generalize to brand-new tasks at inference time.

3. What is Instruction Tuning?

  • Fine-tuning technique to teach models to understand, reason, and follow natural language instructions.
  • Explicit task descriptions (e.g., "predict the sentiment," "translate to Hindi") connect commands to outcomes.
  • Boosts generalization to unseen tasks.
  • Distinct from Prompting: instruction tuning updates model weights; prompting/in-context learning does not.

unseen tasks"]

4. Training Mechanics

  • Objective: instruction + input + prior generated words → predict next word; cross-entropy loss, maximize log-likelihood.
  • Teacher Forcing: actual target outputs fed during training.
  • Architectural Differences:
    • Decoder-only: instruction, input, target output all fed to decoder.
    • Encoder-Decoder: instruction+input → encoder; target output → decoder (teacher forcing).

5. Scaling and Instruction Diversity

  • Diverse Templates: rephrasing instructions multiple ways improves generalization.
  • Task Generation: e.g., SQuAD can be adapted to query-generation and context-generation tasks.
  • Scaling Up: larger model size + more fine-tuning tasks → better performance.
  • Low Compute Cost: instruction fine-tuning costs only 0.2%–1.6% of pre-training compute.
  • Generalizability: gains hold across decoder-only and encoder-decoder architectures.

6. Automated Data Generation (Self-Instruct)

  • Parameter-efficient fine-tuning: alternatives to full fine-tuning, which is memory-intensive.

Small wording changes — order of examples, exact phrasing, punctuation — can produce very different outputs. This makes prompt design more art than science and motivates systematic search.

Lec 23 Advanced Prompting Techniques

Week 8 — Beyond a single prompt. (Supplemented from the course syllabus.)

1. Chain-of-Thought (CoT)

  • Prompt the model to reason step-by-step before giving the final answer ("Let's think step by step").
  • Works because LLMs are better at generation than recall — intermediate reasoning steps help them arrive at correct conclusions.
  • Zero-shot CoT: just append the reasoning trigger to a zero-shot prompt.
  • Few-shot CoT: include a few examples that demonstrate step-by-step reasoning.
Chain-of-Thought Prompting
flowchart TB
    Q["Question"] --> COT["'Let's think step by step'
generate reasoning"]
    COT --> S1["Step 1
break down the problem"]
    S1 --> S2["Step 2
reason about each part"]
    S2 --> S3["Step 3
combine findings"]
    S3 --> A["Final answer"]

2. Self-Consistency

Sample multiple reasoning paths (via temperature), then take a majority vote on the final answers — improves reliability over a single greedy path.

3. Tree / Graph of Thoughts

  • Tree of Thoughts: explore multiple reasoning branches, evaluate/backtrack — a search over thoughts, not tokens.
  • Graph of Thoughts: thoughts can combine, split, and merge (a DAG) — more expressive than linear or tree structures.

4. Prompt Chaining

Decompose a complex task into a sequence of simpler prompts, where each prompt's output feeds the next — improves correctness on multi-step tasks.

5. Retrieval-Augmented Prompting

Fetch relevant documents and inject them into the prompt (RAG, covered in Lec 25) — grounds the model in external knowledge and reduces hallucination.

Takeaway: advanced prompting trades more tokens/compute for higher accuracy by eliciting structured reasoning.

Lec 24 Alignment of LLMs with Human Feedback (RLHF)

Week 8 — Teaching models to be helpful, honest, and harmless. (Supplemented from the course syllabus.)

1. Why Alignment?

Next-word prediction produces a model that can continue text but may be unhelpful, toxic, or evasive. Alignment steers the model toward human preferences.

2. The RLHF Pipeline (three stages)

RLHF Pipeline
flowchart TB
    A["Stage 1: Supervised Fine-Tuning (SFT)
human demonstrations
predict the desired response"] --> B["Stage 2: Reward Model (RM)
humans rank model outputs
reward = predict preference"]
    B --> C["Stage 3: RL (PPO)
policy = SFT model
optimize reward
+ KL penalty to SFT"]
    C --> D["Aligned LLM"]
    D --> E["Deployment + more preference data"] -.-> B

3. The Three Stages in Detail

  • Stage 1 — SFT: fine-tune the pretrained model on curated human-written demonstrations of good responses (behavior cloning).
  • Stage 2 — Reward Model: humans rank model outputs; train a separate model to predict the preference score (e.g., Bradley–Terry).
  • Stage 3 — PPO: treat the SFT model as a policy; reward it with the RM's score while adding a KL penalty to keep it close to the SFT model (prevent reward hacking).

4. Variants and Notes

ApproachKey idea
RLHFHuman preferences → reward model → RL (PPO)
RLAIFAI (a strong LLM) generates the preference labels instead of humans — cheaper, scalable
DPODirect Preference Optimization — skip the reward model; optimize policy directly on preferences
Constitutional AIModel critiques and revises its own outputs against a set of principles

Risk: RLHF can over-optimize (reward hacking), reduce diversity, or introduce new biases — alignment is an ongoing research area.

Lec 25 Retrieval-Augmented Generation (RAG)

Week 9 — Open-book QA: retrieving knowledge instead of memorizing it. (Supplemented from the course syllabus.)

1. Closed-Book vs Open-Book

  • Closed-book: answer from parameters only (parametric memory). Risk of hallucination, hard to update.
  • Open-book: retrieve evidence from a non-parametric external store (documents, knowledge base, web), then answer with the evidence in context.
  • Benefits: up-to-date knowledge, citations, less hallucination, modular (swap the corpus without retraining).

2. The RAG Recipe

Retrieval-Augmented Generation
flowchart LR
    Q["Query / Question"] --> R["Retriever
dense or sparse search"]
    DB["Document store
(chunked, embedded)"] --> R
    R --> C["Top-k passages
added to prompt"]
    C --> G["Generator (LLM)
produces grounded answer"]
    G --> A["Answer with citations"]
  1. Index: split documents into chunks, embed them into vectors.
  2. Retrieve: embed the query, find the k nearest vectors (e.g., dot product / cosine).
  3. Generate: put the retrieved passages into the prompt; the LLM answers using them.

3. Notable Methods

MethodKey idea
REALMJointly pretrain retriever + reader with a masked-language-model objective over a corpus
RAG (Lewis et al.)Retriever + Seq2Seq generator; passages condition the generation
FiD (Fusion-in-Decoder)Encode each passage separately, fuse at the decoder — scales to many passages
UnlimiformerK-nearest-neighbor attention over a long memory, key-value memory networks for QA
KGQA (EmbedKGQA, GrailQA)Retrieve from a knowledge graph via embedding-based or graph-based reasoning

4. When to Use RAG

  • Frequently changing knowledge (news, docs, private data)
  • Need verifiable citations / grounded answers
  • Long-tail factual questions the model can't memorize

Lec 26 Knowledge and Retrieval: Knowledge Graph

Reference video: Lec 26 | Knowledge and Retrieval: Knowledge Graph — Content supplemented from the course syllabus.

1. What is a Knowledge Graph (KG)?

  • A graph where nodes = entities (people, places, concepts) and edges = typed relations ("works at", "born in", "part of").
  • Facts are stored as triples: (head, relation, tail) — e.g., (India, capital, New Delhi).
  • Examples: Freebase, Wikidata, DBpedia, Google Knowledge Graph.
Knowledge Graph — Triples
flowchart LR
    A["India"] -->|"capital"| B["New Delhi"]
    A -->|"official language"| C["Hindi"]
    B -->|"located in"| D["Delhi"]
    C -->|"spoken in"| A
    A -->|"neighbor"| E["Nepal"]

2. KG Representation

  • Symbolic: discrete triples (interpretable, but sparse and hard to query with neural models directly).
  • Embedding-based: map entities and relations into continuous vectors. E.g., TransE enforces h + r ≈ t for valid triples.
\[\text{TransE:} \quad \text{score}(h, r, t) = \lVert h + r - t \rVert\]

3. KG Completion (Link Prediction)

Predict missing links: given two of (h, r, t), infer the third. The embedding model ranks candidate entities by the score.

  • Translational models: TransE, TransR — relation as translation.
  • Tensor/multiplicative models: RESCAL, DistMult — score via tensor decomposition.
  • Neural models: GNNs (see below) and KG embeddings like RotatE (relations as rotations).

4. KG Tasks

TaskGoal
Completion / Link PredictionFill missing triples
Entity/Relation ClassificationLabel nodes or edges
Alignment / Entity MatchingLink the same real-world entity across two KGs
IsomorphismFind structure-preserving mappings between graphs
QA over KG (KGQA)Answer questions by traversing/querying the graph

5. GNNs vs Neural KG Inference

  • GNNs (Graph Neural Networks): learn node representations by message passing over the graph structure — aggregate neighbor features, stack layers. Great for node classification, link prediction.
  • Neural KG inference: typically embedding or attention-based scoring of triples; often treats relations as first-class objects and reasons about paths in the graph.
  • Distinction: GNNs rely on local structure (neighborhoods); KG inference relies on global relation semantics and multi-hop paths — though modern systems combine both.

6. KGs in the LLM Era

  • Grounding: RAG + KG (KGQA) supplies structured, verifiable facts to LLMs.
  • Reducing hallucination: answers traceable to graph triples.
  • Bridging: converting unstructured text to KGs (information extraction) and back (text generation from KGs) is an active research frontier.
